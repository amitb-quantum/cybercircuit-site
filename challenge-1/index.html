Evidence challenge 1, published 21 October 2026

Four bundles. Which ones are real?

These are evidence bundles from one real Cyber-Circuit run, plus the format spec and the receipts a second machine collected while the run happened. Some bundles have been tampered with. Using the spec alone, without our code, decide which bundles are valid and say why.

Download everything (zip) Read the spec

The task

  1. Read the bundle format spec. It is meant to be enough to build a verifier from scratch.
  2. Write your own verifier, in any language. Please don't use CircuitBreaker's code; the point is a second, independent implementation.
  3. Check each of bundle-A to bundle-D with the trusted gateway keys, the trusted log key, and the receipts below.
  4. For each bundle, give a verdict, valid or invalid, and the first check that fails. If you couldn't run a check (for example, no SLH-DSA library), say so rather than skipping it.

First independent answer: 4 of 4

We gave the challenge to Grok, xAI's model, with one instruction: write your own verifier from the spec, without our code. It wrote one in Python, ran every check in the spec, including the post-quantum signatures and live lookups in the public log, and reached the same verdict as our answer key on all four bundles, failing each invalid one at the same check.

BundleWhat we did to itGrok's verdict
AChanged why the trip happened, then re-linked every later record so the journal's own hashes still checked outInvalid, matches (signed checkpoints name journal heads that no longer exist)
BCut the trip out of every file, consistentlyInvalid, matches (checkpoints the second machine received are missing)
CNothingValid, matches
DChanged one byte of one post-quantum signature, leaving the classical one intactInvalid, matches (the post-quantum signature fails)

Grok's verifier and its full check-by-check output are published as written: verifier.py and results.txt (every check passed or failed per bundle, including the live log lookups).

Grok was run by us, so this is an independent implementation, not an independent party. It also listed twelve places where the spec was ambiguous or silent. Those are now answered in spec revision 1.1, which changes no format and no verdict. This challenge keeps the original spec.md as published.

What this does and doesn't test

  • It tests whether the bundle format can be checked by someone else's code, and whether that code catches cuts and rewrites that our own verifier catches.
  • It doesn't test whether the gateway recorded everything that happened, or anything about the agent sandbox. Those are lab results, described on Lab results.
  • The run, the machines, and the spec are ours. An independent verifier is one step toward outside review, not a substitute for it.
